# Oracle policy

Define the oracle before implementation. A test is not an oracle merely
because it passes.

## Allowed oracle classes

### Normative source

Expected behavior comes from an identified standard edition and a reviewed
clause, paragraph, page and raw source span.

### Reviewed golden

Expected output is checked in, reviewed and versioned. Ordinary test execution
must not rewrite it.

### Differential

Equivalent input is run through an independent trusted parser, compiler,
extractor or runtime and a declared observable is compared. Unstable textual
formatting is canonicalized before comparison.

### Metamorphic

A semantics-preserving transformation is applied and a stated invariant is
checked, such as layout normalization preserving tokens or identifier renaming
preserving normalized structure modulo names.

### Negative

An intentionally invalid near-neighbor must fail with a stable diagnostic
class and documented source-span policy, without a crash, hang or silent
acceptance.

## Disallowed

- Expected output generated by the implementation under test.
- Golden files rewritten by normal test runs.
- Compilation success treated as normative or semantic correctness.
- Two implementations sharing the same generator called independent.
- A test that checks only that a trace file exists.

Every central fixture records its ID, content hash, valid/invalid class, oracle
type, expected observable, source locator where applicable, minimization state
and regression status.
