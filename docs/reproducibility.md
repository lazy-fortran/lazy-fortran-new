# Central reproducibility contract

Every verified cross-repository run records:

- repository and component commits;
- clean/dirty state;
- active contract revisions;
- source and fixture hashes;
- compiler, runtime and build-tool versions;
- operating system, architecture, locale and relevant environment;
- exact command line;
- every stage input and output hash;
- trace-manifest and oracle paths.

## Clean-checkout rule

A PASS is valid only when a fresh checkout can run the documented command
without untracked generated files or a developer-local cache.

## Central commands

The commands below are the delivery interface. `verify_active_milestone.sh`
dispatches the active L0 or L1 runner and fails closed for an active milestone
without an implemented runner; a placeholder success is not useful evidence.
`run_e2e.sh` independently fails closed if the L0 runner is absent.

```sh
scripts/check_pins.sh
scripts/check-contracts.sh
scripts/run_e2e.sh
scripts/verify_active_milestone.sh
```

## Artifact policy

Small reviewed manifests and reports may be committed under `artifacts/`.
Large traces and source payloads remain in the ignored run cache and are
referenced by hash. Generated artifacts are either reproducibly regenerated
and checked in, or omitted from version control and generated by a documented
command. They are never both manually editable and declared generated.

## Failure reports

Record the command, exit status, minimized fixture, expected and actual
observables, complete stage trace, hashes, tool versions and owning component.
