# D0094. Adjudicate reference-parser differences against the normative source

Date: 2026-08-15
Status: accepted

## Context

The E0149 comparison of the selected StandardIR projection with the pinned
LFortran Bison parser found both real target gaps and deliberate differences.
LFortran has mature parser factoring, precedence declarations, actions,
extensions and a conflict budget. StandardIR has source rule, page, byte and
hash provenance for each retained alternative and keeps the normative role
categories separate. A reference parser is therefore an oracle for parser
engineering and behavior, not an authority that can silently rewrite
StandardIR.

## Decision

Every comparison finding is classified as one of:

* `target_defect`: our generated output violates the source-backed record or
  a target-tool contract;
* `projection_gap`: a deterministic export mechanism or witness is missing;
* `target_specialization_gap`: the normative records are sound but the parser
  target needs generic factoring, precedence or reachability specialization;
* `expected_difference`: the reference has a different parser-oriented shape,
  extension or implementation concern;
* `standardir_advantage`: our representation provides a stronger property,
  such as normative provenance, source coverage or a clean source boundary;
* `reference_advantage`: the reference provides a property not yet matched by
  our target; or
* `method_gap`: the comparison cannot support a claim yet.

The normative source and its source-backed StandardIR remain the correctness
authority. A reference parser may expose a missing projection, a bad target
normalization or a useful positive property, but its production bodies are
never copied into StandardIR. The comparison ledger must retain both defects
and genuine StandardIR advantages, with exact source locations and a named
next action. “Different” is not itself a defect.

For each selected export, the reproducible comparison consists of: source
projection coverage, duplicate/undefined-target checks, ANTLR4/Bison/tree-
sitter validation, Bison conflict and reachability diagnostics, the pinned
LFortran production inventory, and a manually adjudicated matrix for the
remaining factored families. Counts are regenerated by the experiment script;
the matrix records the judgment that automation cannot establish.

## Rejected

* Treating LFortran's lower raw conflict count as proof that StandardIR is
  wrong.
* Treating a source-backed role alias as a duplicate merely because LFortran
  lowers it into a shared parser nonterminal.
* Calling a grammar better without naming the property and its evidence.
* Using LFortran, Flang or the old grammar corpus as a source for StandardIR
  productions.

## Reversal condition

Write a successor if an independent source or behavior oracle shows that this
classification cannot distinguish a genuine StandardIR defect from a target
specialization or if the matrix omits a comparison lane that changes the
conclusion.
