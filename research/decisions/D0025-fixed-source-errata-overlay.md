# D0025. Fixed source errata overlay

Date: 2026-08-12
Status: accepted

## Context

E0047, regenerated by
`research/experiments/E0047-can-source-controlled-punctuation-witnes/analyse.sh`,
found seven references in the extracted StandardIR SX where a comma or colon
was attached to the reference name. Exact canonical source excerpts show that
each mark is a separate punctuation token. The PDF and its canonical text
remain the source evidence. The derived parser input needs a stable way to
represent these source inconsistencies.

The user directed on 2026-08-12 that a fixed errata layer is acceptable for
inconsistent standard presentation and that a later experiment may test
whether a model can infer the exceptional rule from the common case and the
PDF or extracted text.

## Decision

1. Keep the pinned PDF, canonical text, and authoritative StandardIR records
   unchanged. Apply fixed errata after extraction as a deterministic overlay.
2. Store document-specific overlays under `research/errata/`. Each entry has
   an ID, source hash, source location, exact witness, observed form, derived
   form or rule, kind, origin and evidence run.
3. Use `source-repair` for extraction or layout corrections and
   `parser-exception` for a bounded additional rule required by a documented
   source inconsistency. Derived records retain the erratum ID and the
   generator origin.
4. Accepted errata may feed the compact parser input and its generated wiring.
   The overlay itself is the only maintained exception source. A model may
   propose an entry, but acceptance and application remain deterministic.
5. Later model experiments may test proposal quality against the fixed errata
   set using common-case StandardIR context and PDF or canonical-text input.

## Rejected

Silently normalizing the extracted source is rejected because it erases the
document evidence. Copying a correction from a comparison grammar is rejected
by the provenance boundary. Letting a model apply an exception directly to
parser wiring is rejected because it gives the model structural ownership.

## Reversal condition

Reverse this decision if the overlay cannot preserve the original source
record, if repeated entries reveal a generic extractor defect that should be
fixed upstream, if an entry cannot be checked against the pinned document, or
if the exception set grows until its behavior is less deterministic than a
revised source projection.
