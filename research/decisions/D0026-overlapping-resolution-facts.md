# D0026. Overlapping resolution facts

Date: 2026-08-12
Status: accepted

## Context

E0049 composes the accepted D0019 R402 aliases with the D0025 fixed errata
overlay and the R401/R403 inventory from E0048. Three source terms are in both
families:

```text
scalar-int-constant-name
scalar-int-variable-name
scalar-variable-name
```

The R402 witness resolves each suffix-name term to the parser target `name`,
while the R403 family says that the corresponding `scalar-*` term carries the
scalar relationship. Applying the alias projection alone would erase the
R403 relationship. Applying the expansion alone would discard an accepted
R402 source fact. E0049 therefore records a retained verification failure
rather than choosing an order implicitly. The same composition exercise shows
that `where-construct-name:` first receives a D0025 punctuation token and then
the `where-construct-name` R402 projection. That layering is representable but
must remain provenance-visible.

Evidence: E0049, run R000058, regenerated by
`research/experiments/E0049-can-accepted-resolutions-and-fixed-errat/analyse.sh`.

## Decision

Use a compositional fact set attached to one source term. A term may carry
multiple typed facts, each retaining its own source rule, citation and
resolution class. There is no precedence decision between R402 and R403:
the overlap is an expected composition, not a conflict.

The deterministic lowering order is:

1. apply D0025 punctuation repairs as token operations.
2. lower the R401/R403 `assumed-expansion` fact, including the C401 scalar
   relationship when present.
3. apply the R402 alias projection to the resulting parser target.
4. fuse the resulting direct production and semantic check where the target
   exporter permits it.

The generated source may be fused for compilation speed, but its provenance
maps back to every input fact. The accepted projection retains:

1. the original source term and every source citation.
2. the R402 alias relationship where it is established.
3. the R403 scalar relationship and its C401 constraint.
4. any D0025 punctuation repair as a separate derived token operation.

## Rejected

Treating R402 as having unconditional precedence is rejected because it loses
the scalar fact. Treating R403 as having unconditional precedence is rejected
because it discards an accepted source relationship. Duplicating either fact
in a parser-only table is rejected by D0019. Letting the LLM choose precedence
while generating the parser is rejected by D0016 and D0025. The decision and
the structural projection must remain explicit and deterministic.

A distinct conflict/overlap variant is rejected because it would encode an
ordinary multi-fact case as an exceptional dispatch path. Retaining the
terms unresolved is rejected because both facts are already source-backed and
can be lowered without a new runtime mechanism.

## Reversal condition

Reverse the selected representation if an independently checked projection
cannot preserve both relationships, if diagnostics lose either source rule,
or if the composition requires a second hand-maintained truth. A successor
must retain this overlap evidence and state what the earlier representation
lost.
