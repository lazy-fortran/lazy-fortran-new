## Reference advantages

The pinned LFortran grammar is a parser implementation grammar, not a normative
grammar export. It has a lexer/runtime contract, typed semantic values and
semantic actions; its `units` start symbol accepts a sequence of script units,
and it uses explicit `%left`, `%right`, `%precedence`, `%dprec` and `%expect`
controls. The generated StandardIR Bison file intentionally has syntax only,
so it has no AST actions, semantic values, diagnostics, parser-runtime contract,
or precedence/conflict policy. These are genuine `reference_advantage` results
for the executable-parser boundary.

LFortran also has implementation-specific factoring and extensions, including
`script_unit`, standalone expression handling, fixed/free-form lexer behavior,
and declarations such as `union_type_decl`. Those are not defects in
StandardIR: they are a `scope_difference` between a selected normative
Fortran-2023 grammar root and a production parser. Conversely, StandardIR's
selected root explicitly omits six declared roots (`dtv-type-spec`,
`hex-digit-string`, `numeric-expr`, `scalar-xyz`, `xyz-list`, `xyz-name`), with
seven annotation-only source witnesses. This is a recorded target-scope
boundary, not hidden loss, but it prevents a claim of one complete all-root
parser from this selected replay.

## Defects still open

1. The generated Bison grammar has a much larger conflict surface than the
   pinned LFortran budget (427/2,266 versus 238/180 declared). Bison accepts the
   file because it is GLR and no expected-conflict policy is yet encoded, but
   this is not a resolved parser-quality result. The next deterministic work is
   precedence, ambiguity and language-preservation evidence, not model use.
2. The generated Bison file has no semantic actions or typed values. That is
   correct for the syntax projection but incomplete for a usable frontend.
3. The six omitted declared roots need either an all-root export/replay or a
   permanently documented profile boundary. Their witnesses are present, so
   this is not an untracked source-alternative loss.
4. The comparison does not establish language equivalence. Parser-generator
   acceptance and source identity are structural gates; positive and negative
   Fortran corpus behavior remains a successor experiment.

No production was copied from LFortran. Its grammar was read only to classify
the comparison, and every claimed StandardIR source anchor above is checked
against the generated file and the E0154 source-expression gate.

## Independent Luna review

The minimal D0085 review is retained at
`../E0154-can-exact-source-expression-identity-and/reviews/R000315-luna.md`.
It agrees with the source/provenance advantages and with the open parser-quality
boundary. It also found a lexical-spelling problem that the source-expression
identity checker cannot see: the EBNF projection still prints the PDF's U+2013
and U+2019 in target bodies even though the lexical facts declare ASCII `-` and
`'` as canonical spellings. Direct inspection confirms the EBNF failures at
`grammar.ebnf:1325`, `2398`, `2861`, `1450`, `1541`, `2143` and `2532`.
The other three formats map the target terminals to the canonical ASCII
spellings while retaining the Unicode scalars in comments. This is recorded as
`target_defect`/`projection_gap`, not as a source-identity failure.

until its four-format lexical witness gate passes.
