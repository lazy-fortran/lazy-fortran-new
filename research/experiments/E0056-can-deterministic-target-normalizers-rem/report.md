# E0056. Deterministic target-export structural normalization

Generated by `research/experiments/E0056-can-deterministic-target-normalizers-rem/analyse.sh`.

## Question

Can deterministic target normalizers remove the E0055 structural export
boundary without changing StandardIR or source provenance?

## Method

The analysis reruns E0055 and checks its composite-input hash. It applies only
target-side transformations: three mutually recursive expression families are
rewritten into iterative precedence forms, five named nullable wrappers are
inlined, and tree-sitter receives an explicit conflict table for the
ambiguities already exposed by its generator. ANTLR4, Bison and tree-sitter
then validate the resulting target files. A declared normalized-rule mutation
must fail its witness check.

The normalizer makes no model calls and does not alter StandardIR, the source
record count, or source citations.

## Result

ANTLR4 and Bison generate successfully. ANTLR4 retains 18 warnings and Bison
retains 206 warnings because the exports preserve all source productions and
their target-specific reachability or redundancy diagnostics. Tree-sitter
accepts the generated JavaScript and resolves all emitted names, but generation
stops at the next unresolved conflict between the literal constant and kind
parameter forms.

## Boundary

The compact generic adapter is established for recursion, nullability and
target conflict representation. Continuing to make tree-sitter generate now
requires an expanding Fortran-specific ambiguity table. The next unresolved
group is `r_int_x2D_literal_x2D_constant` versus `r_kind_x2D_param` after a
shared `r_digit_x2D_string` prefix. This is retained as the next explicit
boundary rather than being hidden in a growing exception list.

No model calls were made. The result supports D0028: local target projection
logic remains deterministic, and no model is needed for wiring or composition.
