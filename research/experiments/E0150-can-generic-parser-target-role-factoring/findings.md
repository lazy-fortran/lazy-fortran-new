# E0150 role-family factoring

Reproduce the current all-family probe with:

```text
research/experiments/E0150-can-generic-parser-target-role-factoring/analyse.sh \
  .cache/runs/E0150/R000007
```

The optional second argument selects one mechanically discovered
representative family. The current family cells were run for the targets
listed in `R000008` through `R000015`; the command and target are recorded in
each run's `summary.json`. The input is the selected-root Bison export from
E0147/R000022 at `standard-new` `c955c23bd57a078c8fceb30de1df101280b25e2c`.

## Result

The baseline in R000007 has 1,341 production heads, 2,293 alternatives and
427 shift/reduce plus 2,266 reduce/reduce conflicts. Bison also reports four
useless nonterminals and seven useless rules. The baseline and candidate
metrics are regenerated by the command above; they are not hand-counted.

Factoring every mechanically discovered whole-production unit alias is safe
with respect to the prototype's deletion bug fixed in `factor.py`, but it is
not a useful default: R000007 changes the conflict counts to 472 shift/reduce
and 2,450 reduce/reduce. It retains the same useless-rule diagnostics and has
no language-preservation witness.

The per-family sweep is more informative. R000008 factors the four aliases
that resolve mechanically to `r_data_x2D_ref` and changes the counts to 425
shift/reduce and 2,135 reduce/reduce without increasing useless rules.
The other seven discovered families either leave the counts unchanged or
increase them. This is evidence for a generic parser-target specialization
mechanism, not a license to erase the distinct source roles. The alias map
and source lineage must remain available to the semantic frontend.

The first exploratory prototype, R000001, treated a unit alternative inside a
multi-alternative production as if it were the whole production. It appeared
to reduce conflicts to 0/3 but produced 795 useless nonterminals and 1,192
useless rules. That result is retained as a failure. The generic invariant is
now explicit: only a production with exactly one alternative can be a unit
alias.

## Adjudication against LFortran

The pinned LFortran Bison grammar is a parser-engineering reference. Its
lower raw conflict counts result from hand-maintained role factoring,
precedence declarations, actions and accepted extensions; they do not prove
that the source-backed StandardIR is wrong. StandardIR is genuinely stronger
for normative provenance: each retained alternative is tied to J3-24-007 rule,
page, byte span and source hash. It also preserves the normative role
categories instead of silently replacing them with LFortran's parser nodes.

The current manual comparison therefore has three separate outcomes:

* target/projection defects become generic production fixes;
* parser-target differences become deterministic specialization candidates
  with preservation witnesses;
* source-backed provenance and role distinctions remain positive results when
  the reference does not provide them.

No LFortran production body is copied into StandardIR. No named Fortran rule is
hand-repaired by this experiment.

## Remaining gate

The useful `r_data_x2D_ref` candidate still lacks an independent language or
corpus-preservation witness. The selected export also still reports four
parser-useless nonterminals and seven parser-useless rules. The next slice is
therefore a generic source-role-to-target-role factoring pass with a retained
mapping, parser reachability witness and independent corpus checks. Until that
slice is complete, M2 is open and semantic/model work remains frozen.
