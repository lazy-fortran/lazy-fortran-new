# Luna review of E0152

The experiment is useful as a traceable selected-root projection and
cross-format inventory, but it does not yet represent the Fortran 2023
language adequately. It supports structural consistency after normalization,
not source completeness, parser correctness or language equivalence.

## Findings

1. The original alternative counters were defective. Tree-sitter counted one
   alternative per head, and the ANTLR4 counter mishandled split-colon/comment
   forms. The corrected inventory now reports EBNF 1,188, ANTLR4 1,197, Bison
   2,286 and tree-sitter 1,231 alternatives. These remain structural counts,
   not language metrics.
2. Flang's count is only `Rxxx` comment occurrences, not grammar alternatives,
   and its pinned source header says it is derived from the Fortran 2018 draft.
   It is useful as an LLVM parser/rule-ID comparison, not a Fortran 2023
   language denominator.
3. The generated formats have 1,191 provenance headers and the same 1,031
   unique lineage identifiers; the exact lineage sets agree. This still does
   not compare normalized RHS bodies.
4. The inherited source-projection report covers 1,061/1,068 alternatives,
   skips seven explicitly and reports zero missing/header gaps. Its body-bound
   witness would accept a wrong RHS with the same lineage; D0087/D0088 require
   a source-expression identity witness before M2 closes.
5. The selected output remains parser-unhealthy as a production target: Bison
   reports 427 shift/reduce and 2,266 reduce/reduce conflicts. Validator PASS
   means the target file is accepted by the tool, not that the language is
   disambiguated or behaviorally equivalent.
6. The five-token lexer companion is not complete fixed/free-form lexical
   behavior, and the selected profile is not full Fortran 2023 coverage.

## Bidirectional advantages

StandardIR is genuinely stronger in source rule/page/byte/hash lineage,
preserved normative roles, explicit omission accounting, one source for four
exports, and keeping parser actions/extensions out of the normative input.

LFortran is genuinely stronger in executable `yylex`/`yyerror`, typed token
values, token payloads, precedence, AST actions, parser-oriented factoring and
an explicit 238/180 conflict budget. Neither direction licenses copying
productions or inferring normative corrections.
