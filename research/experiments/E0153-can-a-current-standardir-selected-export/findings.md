## Result

All seven current source anchors pass the deterministic check, and ANTLR4,
Bison, tree-sitter and source projection pass independently. The run verifies
the four generated-export hashes, the inherited validator-report hash and
materializes the pinned LFortran reference into its own run directory. The current
candidate therefore does not reproduce the old R741/R843/R1307/R1315
truncation or tokenization critique. R1416/R1417/R1418 are also complete; the
two R1416 source occurrences are retained as lineage and merged only in the
target body.

The current candidate is stronger than LFortran in a specific, documented
sense: every retained target alternative has J3 document, rule, page, byte and
source-hash lineage; the same source-backed records feed four export formats;
normative role categories and source optionality remain visible; and parser
actions and implementation extensions are not silently mixed into the
normative representation. The current output is also more mechanically
auditable because its source projection and mutation controls are explicit.

LFortran is stronger in a different, equally concrete sense: its Bison target
has an executable `yylex`, typed semantic values, token payloads, precedence
and associativity declarations, AST/trivia actions, parser-oriented role
factoring, and an explicit `%expect 238` / `%expect-rr 180` conflict budget.
The current StandardIR Bison export has no executable lexer or AST actions and
reports 427 shift/reduce plus 2,266 reduce/reduce conflicts. Those are genuine
target-specialization and runtime gaps, not evidence that the source-backed
productions are wrong.

The raw counts are not comparable as a language score: the current generated
target has 1,337 heads and 2,286 alternatives because it preserves normative
roles and generates helpers, while LFortran has 238 heads and 1,006
alternatives after hand factoring and includes parser-oriented forms. The
remaining M2 work is therefore explicit: derive generic role factoring,
precedence and lexer/runtime contracts from source-backed metadata, then prove
language preservation on a positive/negative corpus. No LFortran production or
action is copied.

The deterministic anchor check is intentionally only a regression screen: it
checks required token/name presence, not full source-expression identity. A
future source-expression witness must replace that weak check before M2.
