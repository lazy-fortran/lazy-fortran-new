# E0074 report

All values and generated files below are regenerated by
`research/experiments/E0074-can-the-accepted-e0072-aliases-integrate/analyse.sh`.
The analyzer is pinned to `lazy-fortran-new` commit `3210899` and makes no
experimental model calls.

## Question

Can the accepted E0072 aliases integrate with the complete syntax projection
and direct wiring while semantic facts remain separate?

## Method

The analysis reruns E0072, checks the pinned syntax and fact hashes, and applies
only its three alias records to the 522 E0013 syntax records. It writes the 29
semantic-role records to a separate table. The four StandardIR exporters then
emit EBNF, ANTLR4, Bison and tree-sitter files from the integrated syntax.

A source-driven traversal recomputes the six alias reference rewrites and the
178 unresolved names with no guessed resolution. It also emits one direct
dispatch row per syntax record, preserving source rule, page and source hash;
encoded identifier spellings avoid collisions from punctuation in StandardIR
lhs names. The direct Fortran module is compiled with warnings as errors.

The full target validators are run separately. Their rejection is an expected
boundary when unresolved names remain; it is not converted into a guessed
parser rule. One source term, `type-name`, has both a parser alias and a
semantic-role fact. That overlap is retained as two typed facts; the semantic
fact key does not enter the parser projection.
